# Changelog

Every release is listed here, newest first. Versions look like `0.MINOR.PATCH-beta`; [BETA.md](docs/beta/BETA.md) explains what the numbers mean. Back up your database before every update. A release that changes the database says so at the top.

## 0.75.3-beta

No database change: install it over 0.75.x as usual. Fixes for the problems reported on GitHub (issue numbers in brackets), the Discord server, and a wiki with step-by-step guides.

### Fixed

- Time of day: the day clock the client runs is now the server's game clock, sent in the first world packet (0x00E6) and in the map change packet (0x009A), where the server used to send a constant and a random token. A map change no longer jumps the time (it showed about 7:05 PM), and the night the player sees is the night the server tests, so quests that need the night phase (CheckDailyValue) can progress when the screen is dark. (#24)
- Job change: the character list now shows the changed job (the type of the first job change is sent in the list entry instead of always the base job), and the job that NPCs, the skill master and the spawn use is the highest job the character holds, as the original server sets it. Before, a changed character looked like its base job after a relog, was refused by the Warrior master as not being the base job, and could turn invisible after a map change. (#18, #26)
- Equipment bought or received for a changed job (the cape of the first job change, for example) can be worn: the class check of an item now uses the character's current type (10 to 24 after a job change), as the original does, instead of the base type chosen at creation. (#24)
- Bosses with kill items (Kaboom and the Growth Badge, for example): the item given from the boss is now announced as the original does, with S2C 0x0256 (boss, item, receiver) sent to the players around the boss, so the client shows the item received from the boss instead of only a line in the chat window. (#19)
- Harcon Defence: a new room no longer closes while the host is moved to the waiting room. The warp to another map hands the player to a new connection, and the old connection used to take the player out of the room as if he had left; a hand-off now keeps the player in the room (it is released only if he does not arrive within the warp time). (#6)
- Harcon Defence: the room member list shows the host once, and the number beside a member's name is the character level instead of the entity id. (#7)
- Harcon Defence: the coin shop in the waiting room shows the character's coins and accepts purchases; the coin balance is sent when the player arrives on a waiting map, not only when the lobby is opened. (#8)
- Harcon Defence: choosing the coin shop closes the NPC dialog before the shop window opens, as the other NPC windows do. (#16)
- Delay on attacking, picking up and drilling: the servers now send every packet at once (TCP no-delay) instead of letting the system hold small packets back until the client acknowledges the previous ones, which stretched replies made of many small packets to a second or more on real networks. Candidate fix, not yet confirmed by the reporter (#5).
- Aggressive monsters now attack: every half second an aggressive monster looks for the nearest player inside its view range and goes for them, as the original's aggressive attack strategy does; before, the server only noted the target in its log (#14).
- Area skills such as Quake Hammer and Hammer Wheel no longer hit shadow-world monsters unless the player has the Third Eye (mind's eye) effect, as the original's area target collection requires (#15).
- Quake Hammer shows its damage numbers and hit effects: I now close the cast block (header and end marker) as soon as it is sent and send each monster's hit outside any block, as the original's skill library does (the 1530 cast block holds only its header, the hits come from the per-target 1531 effect through the normal hit message). (#11)
- Day and night music: Rose Garden Field 1 and the other maps play the music of the current time of day, because the client now gets the shared game clock described above when it enters the world and when it changes map (#17).
- Logging out on a map that returns the character (zone type 6 or 8, class 3, or map option 4 in the map table) now saves the character on the return map, so the next login starts there instead of on the same map (#10).
- Shift + click and a click while sitting now turn the character toward the clicked point without moving: the server answers the client's face request (0x0041) with the same turn frame to the player and the players around, as the original does (#12).
- Attacking a moving monster: the character no longer keeps chasing until the monster stops. While a chase leg is running I now check each tick whether the monster is inside the weapon's attack range at its current position, and if so I stop the leg with a stop packet at the character's real position and start the swing, instead of waiting for the leg to end at the point where the monster used to stand. (#13)
- Kaboom and the other multi-bar bosses show all their HP bars: the target info packet (S2C 0x0121, sent when the player clicks a monster) now carries the bar count and the boss flag, which the client needs to switch to its boss HP bar. Before, I sent zeros in those two fields, so the client opened the normal one-bar HP bar and the later HP updates (0x011E) could not change it. (#20)
- Job change quests: after the quest is completed the master now shows the quest's own message with the Advance button (the quest result table's message, which the client asks for as page q4), so the job change window opens straight away. Before, I refused those pages, so the dialog closed and I had to talk to the master again. The accept message (q0) is shown the same way. (#24)
- Movement: the walk and run speed I simulate for a character is now exactly the speed the client draws. The client moves at the announced speed byte times 4, so I now announce trunc(speed / 4), as the original game server does, from the real speed (items and effects included), and I walk the character on the server at that same value instead of 115 while the client drew 112.
- `tposeidon start` no longer reports that the lobby did not open its port on Windows builds where the system's listener list omits it: when the list does not show the port, the check now also tries to connect to it (#9).

## 0.75.2-beta

No database change: install over 0.75.0 as usual. Fixes for what 0.75 added and for reported problems, and three tools for server owners that players asked for.

### Added

- Player accounts: `tposeidon account add <name>`, `account password <name>` and `account list` create accounts for your players, set a new password and show the accounts (created date, GM and membership marks). The panel's GM window has the same on **Players**, **Accounts**. A name that exists is refused instead of kept silently, and names and passwords follow the 19 byte limit of the game client's login.
- My Camp: **Give all shown** in the GM window's Give item (My Camp category) gives every My Camp item the search lists to the character's account in one database step, after a confirm that states the count and the account, and reports how many were added and how many skipped. The command line has the same: `tposeidon camp --character <name> --all-matching <text>`.
- Character slots per account: how many characters an account can hold is now a setting you choose (the original servers allow 3, which stays the default). Use the Character slots page of the setup wizard, the panel's "..." menu (Character slots per account...), `tposeidon setup --character-slots <1-8>`, or `characterSlots` in the settings file; 8 is the number of character cards the game client shows. Restart the servers after changing it. Lowering it never removes characters: an account that already has more keeps and can play them all, and cannot create another until it is under the limit. The character list unlocks every card up to the highest slot an account uses, so a character is never shown in a locked card.

### Fixed

- Korean character names: creating a character with a Korean name no longer fails with "This character name is unavailable (1019)". Character creation now uses the original's name rule (4 to 16 bytes, Korean allowed), the same one the rename item already used.
- Character select showed 8 open slots while the server allows 3, so a fourth character failed with 1020. The open slots now match the server's limit (see Character slots per account).
- "Move to starting screen" in the game no longer freezes the client for players who logged in with Play or the launcher. The client logs in again with the same login pass, which the lobby used to refuse after the first login; a used pass now stays valid for that account from the same address for 12 hours after the last login, and a new Play or launcher login replaces it.
- Client check and Play with clients whose game data was rewritten by other tools (double quotes and no spaces in the table lines, as in some shared client packs): the check no longer reports present map rows as missing, its fixes add only what is really missing instead of stopping with "libconfig has no table MapInfoEx", and the libconfig index written for Play lists every table again.
- Client check in the panel: an unexpected error during a fix no longer closes the panel. The error is shown in the check window and written to the panel log, and the window keeps working.
- Second password (padlock): an account that already has a padlock is no longer offered to create one after every login. The character list now carries the account's padlock state, as the original server does.

## 0.75.0-beta

**This release changes the database** (changes 083, 084, 087, 088 and 089 below). They apply on the first start, once; `tposeidon start` offers a backup first, and it now works with PostgreSQL in Docker too. Back up your database before you update. The first start also rebuilds the server's world data, so it takes a little longer.

**Releases are for Windows only from now on.** The Linux and macOS packages are withdrawn until version 1.0: we will test them ourselves first.

**The PC-room EXP and TM rates now need membership.** They used to apply to every player; see the account membership entry below.

Database change 083: the megaphone queue (two columns on the broadcast table and a state log table). It applies on start.

Database change 084: the guild emblem (six columns on the guild table). It applies on start.

Database change 087: the saved class skills of a game master in GM mode (two tables). It applies on start.

Database change 088: the account membership switch (one column on the accounts table). It applies on start.

Database change 089: the Shadow Sanctuary reward a character holds (one table, one row per character). It applies on start.

- Added: setup and Play now add the map rows the Shadow Sanctuary and Harcon Sanctuary maps need to your own client data: 11 rows in `MapInfoEx` and 11 in `MonsterScenario` (maps 549 to 556 and 562 to 564), written into the libconfig file of the chosen client mode together with its index. The original files are kept as `libconfig.dat.tposeidon-original` and `libconfig.idx.tposeidon-original` (or the `_eng` names), the change is skipped when the rows are already there or when the client is running, and the servers rebuild their world data once afterwards. A client with the rows is not changed. No game files are shipped; the rows are values built into tPoseidon.
- Added: the Shadow Sanctuary statue event. Eight timer rows (`Npc_TimeTable` 800 to 807, daily at 23:00, 01:00, 11:00, 13:00, 15:00, 17:00, 19:00 and 21:00, 20 minutes each) and eight `TeleportInfo` rows are added to the client data with the map rows, and the teleport NPC (shadow NPC 17176) in the eight town tables is linked to its timer; the client shows it only while its window is open. The server opens each window: it shows the NPC, starts the sanctuary (five Harcon statues, the scenario steps of the map, a 20 minute clock, the statue board every 5 seconds with the top six players and guilds), counts kills per player and guild, ends the event on the boss kill (success), a fallen statue (failure) or the end of the window (success), sends the result, lets the players stay 30 seconds after a success or 9 seconds after a failure and then sends them to their home town. Rank 1 (the winner or the winning guild) and rank 2 (everyone else) of the `ShadowResult` rows give stat bonuses for 3 hours that survive logout (database change 089). The shadow monsters reach and strike the statues the way the original does: they pick the statue as their target through the `ShadowAI` table and fight it in the ordinary monster battle, with the monster swing and its frames, instead of the earlier fixed strike. The zone sends its phase to the players when it opens and when it ends. The area reward of rank 3 (`MonRdecr`) lowers the combat stats of the monsters of the whole world map region for 3 hours after a success. The three Harcon Sanctuaries (maps 562 to 564) run the same way, on six more timers (`Npc_TimeTable` 808 to 813, at 12:00, 14:00, 16:00, 18:00, 20:00 and 22:00, 20 minutes each), three `TeleportInfo` rows (808 to 810) and the six NPC 1176 rows of `NpcTalk_Path_NE`, added to the client data with the other rows.
- New: the monster scenario of map 616 (the Harcon map of the Poseidon episode), as the original runs it. Every player who enters gets a private copy of the map that only he can see monsters in. His run starts at once: the Harcon of the boss table is placed at every point of its region, then the ScMon_EP6 table is played from the clock of the run, one row per tick once its time in seconds has passed. A normal row spawns its monsters in its region (never more than 20 live monsters, except the boss types), a row with condition 7 spawns one monster that shouts to the player (S2C 0x045D with the monster, the skill and the text) and the row comment goes out as a notice (S2C 0x04DE). When the Harcon dies the run fails and stops (S2C 0x04E7 with 0), when the boss dies it reports the win (0x04E7 with 1). At most three runs are active at the same time on the map, as in the original.
- Changed: players in different copies of an instanced map (map 616) no longer see each other. Movement, chat, speed changes, spawns, titles, signs, pets and guardians now reach only the players of the same copy; ordinary maps behave as before.
- New: the skills shouted in the map 616 scenario now hit the player. Each shout (Unshield, Dark Slow, Flash Attacking) is cast by the monster that was spawned for it on the player of the copy right after the shout frame, through the ordinary monster skill casting. When the Harcon dies or the boss dies, every player of the copy whose return zone is set (1 to 999) is sent back to it after 15 seconds. The scenario conditions 4, 5, 6, 8 and 9 are built as well (monsters keyed by the check monster, kills of the check monster, zone players minus own monsters, and a spawn of the row count per zone player).
- New: the Shadow Sanctuary rewards now go through the Master, as in the original. The reward a character wins (Master 0x0C20) is saved by the Master, and the area reward of rank 3 (0x0C22, relayed as 0x0C23) reaches every game server, so the monsters of the region are weakened on all of them, not only on the server that ran the event. The game server saves the reward itself while the Master is not running.
- New: shadow monsters of AIType 0 no longer hurt players, as in the original (they only fight their target monster; the other AI types hurt anyone). Shadow monsters of AIType 2 keep their first target until it is inside their view range, then turn to the nearest target in range.
- New: the shadow monsters of the ShadowAI table now go for their target monster. Every half second a shadow monster picks its target (the monster of the TargetID in its copy: the first one it holds for AIType 0 and 3, the nearest one for 1 and 2), retargets from a player to it and chases it for 5 seconds; monsters without a ShadowAI row are unchanged.
- Changed: the boss kill history of a player now travels with the character from the Master to the game server, as the original does when it loads a character, instead of being asked for separately: the inspect window, the login batch and the window refresh after a boss kill use the list the game server already holds. The separate Master request for the history is gone.
- Changed: the client folder scanner now tells real problems from things that need nothing. Shop and skill shop NPCs are no longer reported for their character type (the server places them with any type), monster regions without a spawn point of their own and map files that no game data uses are shown as notes instead of warnings, and a new fix adds the two map rows the client data points to but does not define (Beginner's Square - Monster Guild, Ice Prison). On a real KR 2014 client this took the scan from 309 warnings to 15.
- New: the client folder scanner. Right after you choose the client folder, setup scans it (in the first-run wizard, in the panel's setup window and in `tposeidon setup`) and lists what the emulator needs: the client program (the KR 2014 build with the lobby addresses and the packet key table), the libconfig, index and font set for the client language, the level and stat charts, the map folder, the address in the client, the client's settings in the registry (read only) and whether the client is running. It also checks the world data the server builds from the client: every portal has a destination map with an arrival point, every NPC, shop and skill shop point of the NPC tables exists on its map and has a picture, monster spawn regions exist on their maps, and every map file has a MapInfoEx row and the other way round. World findings are listed by map. One Fix button applies every fix that is offered, each finding that has a fix has its own button, and Restore originals puts back what the scanner changed. Fixes keep a backup: the missing libconfig set is copied from the other set (and removed again on restore), the Shadow Sanctuary and Harcon Sanctuary map rows are added to the libconfig file (the same fix setup and Play already run), the address patch keeps `Trickster.bin.tposeidon-original`, and corrected map points are written into a copy of the map file with the original kept as `.tposeidon-original`. Fixes are refused while the client runs. Command line: `tposeidon client check` and `tposeidon client fix [--restore] [--only <fix>]`, both with an optional `--client <folder>`. Findings with no known correct value are reported only and say why. The list of corrected map points is empty until values are confirmed from evidence.
- Fixed: the inspect window of another player now shows the stat figures the way the original computes them. The "+n" bonus of each stat leaves out the share added by the game master ability percentages (the original adds only worn items, buffs and flat bonuses), the stat levels, remainders and table values count the party class bonus points, and the body type and job shown come from the appearance the character wears and the highest job learned, instead of the base species for both.
- Elemental blessings (Undine, Raion, Salamander, Gnome and Sylph): the counter hit of each blessing now carries its own flag in the hit record, as the original (water 0x08, thunder 0x10, fire 0x20, earth 0x40, wind 0x80; it was 0x08 for all five), a blessing answers only hits that do not carry its own flag, and a counter hit on a monster is followed by the monster hit message (S2C 0x039B: monster, attacker and the 28-byte hit record) that makes the client play the counter hit effect of that flag.
- Party quests: the client's request for its held party quest (C2S 0x04AF, which was ignored until now) is answered with the record of the original (S2C 0x04B0): one byte 0 when no party quest is held, otherwise the party number, quest, monster type, own kills, target count, member count, the time left when the quest was cleared (0 until then), the cleared flag and the number of completions.
- New: account membership, as in the original. A member account gets 20 percent more walk, run and chase speed and the PC-room EXP and TM rates; everybody else gets neither. Everyone is off by default. Turn it on with `tposeidon gm member <account> on` (off to remove it, `tposeidon gm member list` to see the members), with the Membership buttons in the Players tab of the panel's GM window, or with `@member <character> on|off` in game; it takes effect at the account's next login or zone change. Note: the PC-room EXP and TM rates from the rates file (EXP_PCRoom, TM_PCRoom) used to be given to every player and now need membership, so a server that relied on them must make its players members.
- Guild games: watchers are hidden from the fighters. The original server flags a watcher invisible and observer, and the client then neither draws nor targets that character; a watcher is now also never announced to a fighter (no spawn when the watcher arrives or comes into view, none of the watcher's actions are broadcast to fighters), and a defeated Team Deathmatch player is removed from the fighters' view when they rise. Watchers and defeated players still see each other and the fighters.
- Guild games: a watcher and a defeated Team Deathmatch player now enter the spectator state of the client. The client takes its spectator state from the flag word in the spawn of its own character (the four bytes after the level): the observer bit (0x400) switches the guild game screens to the watching view and the invisible bit (0x10) hides the character. The spawn sent when a watcher arrives, when a defeated player rises and to the others now carries the word of the original (block 0x08, fast move state 4, invisible 0x10, observer 0x400). The original's extra notice (S2C 0x02A9) is not sent: the client has no handler for it.
- Guild games: the best fighter of the winning team is now rewarded in every match type, as in the original. When a match ends with a winner, the best fighter (most kills for Team Match and Team Deathmatch, highest score for Monster Match, with the original's tie-breaks by defeats, level and experience) gets the items of the reward table (GuildGameRewardInfo) row chosen by the average ladder rating of the two guilds, and sees the reward list in the client (S2C 0x02D0). As in the original, an average above 1100 gives the 1100 row and an average of 1100 or less gives nothing; a guild without ladder games counts as 1000.
- My Camp: the owner of an open camp now gets the expiry notices of the original for time-limited camp items (S2C 0x02F3). Once a minute the camp checks the time left of each timed item that is new or placed, and reports it once when it falls to 1440, 60, 5 and 0 minutes (the item leaves the check at 0). A time-limited camp item is one flagged as such with a use date and a use time in hours. Not live-tested; no camp item in the data is time-limited yet, so nothing shows until one is bought.
- Added: bosses of the boss table (BossMonsterparamEx) have several HP bars, as the original. A boss with a life count of N has N more bars after the first; each time a bar is emptied the next one refills from the overflow of the blow, every element resist of the boss rises by the table's minimum growth and the element the players hurt it with most since the last bar rises by the maximum, the boss says its resist line, and the client plays the resist effect (S2C 0x0346 and the monster speech 0x00B8). The boss dies when the last bar is empty (S2C 0x02AC with the earthquake flag of the table). A boss that nobody attacks for 50 seconds gets all its bars back and loses the resist it gained. The HP updates (0x011E) now carry the bar count and the boss flag. A boss that is under attack calls its minions when its summon timer runs out and it has lost enough bars: S2C 0x02AB, then 2 to SummonMax-1 children of the table's four summon types appear around it (not on blocked cells, never more than the table's total), then it says its summon line. The children disappear when the boss dies and after 100 seconds without an attacker while the boss has lost no bar. The Doppelganger of the Office Dungeon (monster 2633, children 2634) now works on the same machinery: it has its bars and minions, and the player who entered the map last is told to show it and its children with his own look (S2C 0x0434 for the Doppelganger, 0x0437 for each child), as the original.
- Fixed: the damage that decides which element a boss grows most resistant to is now counted for every kind of hit, as the original: tornado, chain skills, the polar bear, throwing knives and gun shots (physical or gun element) and the blows of monsters count too, not only melee and the element skills.
- Fixed: the Doppelganger of the Office Dungeon (monster 2633) no longer gives the kill items of its boss table row (items 103, 104, 105) to the players who hurt it most. The original gives them only from the kill routine of the boss class; the Doppelganger class never calls it, and its children have no row. It pays its normal drop table, experience and TM as before.
- Added: a boss that has just lost a bar cannot be hurt for 2 seconds, as the original: melee blows on it are blocked without damage, skill and shot damage does nothing, and those hits do not count toward the element it grows resistant to. The boss keeps moving and attacking meanwhile.
- Added: bosses heal and cast their own skills, as the original. On each heal time of its row the boss looks at its two heal slots in order; when it has lost enough bars, its HP is not full and a coin flip comes up, it casts its heal skill (5101) on itself at the slot's level. On each skill time it looks at its skill slots in order; when it has lost enough bars, someone is attacking it and one roll in five comes up, it casts the slot's skill at its target, and the time of that slot sets the next check. The Doppelganger heals the same way; its skill check never casts, as in the original, whose copy of that check only accepts a slot of level 0 and a level 0 cast is refused.

- Fixed: a card battle that takes a card from the loser now reports the bag change as the original does: the winner gets one list of bag operations (message 0x0104) and the loser gets the matching list (message 0x0106), instead of single item operations.
- Fixed: the couple memos of the original are sent. When a couple breaks up, when a divorce is confirmed and when a divorce is refused, the partner receives the memo "BreakUpMsg" or "CancelDivorce" from the game's own text table with the sender's name (message 0x2EB3); a partner who is not logged in gets it as an offline message of the friend list.
- Fixed: the boss kill list of the inspect window is now in the order of first kills, as the original stores and loads it, instead of by monster number.
- Megaphone: a shout whose system servers have not all answered by the next turn now makes the master server check every system server (messages 0x15AA and 0x15AB, as the original), and posts the shout again once all of them answered.
- My Camp: the warehouse button of the camp window works. The owner of a camp opens his warehouse from inside the camp (C2S 0x02FE) for free, as the original; the request was only logged before.
- New: party member follow. Pick a party member in your map and choose follow: your character then runs after that member by itself (S2C 0x0216 shows "following from now on" with the member's name), stopping at 96 units from them and checking again every half second, at the run or walk speed your weight allows. It stops when you move or act yourself, when you or the member die or leave the party or the map, and tells you so (S2C 0x0217). Choosing a player who is not in your party is refused with the not available message. When the member you follow walks into a portal, you are sent through the same portal with them (S2C 0x02FA, then your client asks for the portal itself).
- Added: the server reads the height layer of the map files (the fourth layer, the same file the client loads) and uses it for the original's line-of-fire rule. A gun shot whose line crosses ground that is too high is not fired: the shooter's swing shows and the client gets its 'cannot shoot, blocked' answer, with no damage and no bullet used. The skill Beast Claw needs level ground between the caster and the target and is refused with the client's code 13 otherwise. Maps built into a world snapshot before this change carry no height layer and are treated as flat until the snapshot is built again.
- Added: asking for a card battle title while standing near a map portal or next to an NPC, shop or skill shop point is refused with the client's 'too close' answer, as the original does (the allowed distance is the original's margin around the point or portal area).
- Shadow monsters and your guardian, as in the original: a shadow monster (monster ids 16000 to 16999, the ones only a player under Third Eye can see and target) no longer gives your guardian experience on every hit like a normal monster. Your guardian gets experience when you kill one instead: the monster's maximum HP times 0.3 (the SoulGuardianExp row for shadow monsters), times 0.25 of the level ratio when the monster's level is below the guardian's. Third Eye itself needs no server rule: the client decides what you see and can target, and the shadow NPCs of the towns (ids 17000 to 17999) already stand and talk like any other NPC.
- Added: guild rank bonus experience. The SystemServer now ranks the guilds once a week (Monday, by the week's guild points, then ladder score, member count and newest guild first, as the original's weekly ranking procedure does), stores the ranking history and zeroes the week points. Members of the guilds ranked 1 to 10 get extra EXP and TM EXP on every gain (the GuildRankBonusExp table: 20% for rank 1, 10% for rank 2, 5% for ranks 3 to 10), and the client shows the guild bonus notice when the bonus changes. The bonus is checked on entering a map and once a minute. The weekday and hour of the original's ranking job are not in the data we have, so Monday is our choice.
- Added: a monster under the Vampiric state (monster skill 1460) now heals after each hit it takes, as the original does: it recovers the damage minus one hundredth of its maximum HP, capped at its maximum HP, and the client plays the dracula effect with the healed number. A hit that kills the monster does not heal it. All damage paths go through one shared monster-damage hook; damage amounts and the packets they send are unchanged.
- Timed items: pet level up, pet merge, equipment merge and the key box now give a time-limited result item its expiry and register its timer with the client (S2C 0x0324 before the result frame), as the original does.
- Fixed: the GM OX quiz now shows the question and the correct answer on screen as the original does. The question text reaches everyone on the OX map (a question of just 5 starts the countdown instead), and the answer order shows the correct-answer word followed by O or X. Both orders are ignored outside the two OX maps, and the answer plays its sound only for the players standing on the right side while the players on the wrong side are moved to their return map two seconds later, as the original does (the sides are the O and X marks in the second cell layer of the map).
- Timed items: the egg shop (VIP shop) and the gift box now register the timer of a time-limited item they give, with the registration frame (S2C 0x0324) sent before the result frame, as the original does. Taking a post with a timed item puts its expiry in the item's timer field of the take reply, where it was always empty before. Compound gives no timer, as the original.
- Changed: a card battle title request is now ignored inside a My Camp (the original only handles it in a field zone), where it used to be broadcast.
- Changed: the character data frame (S2C 0x02A7) and the character info at the start of the growth reset answer (S2C 0x0289) are now 73 bytes, as the original sends; the four added bytes are the high half of the couple code and are zero.
- Changed: the character data frame sent when entering the world (S2C 0x02A7) now carries the creation time of the character in its time field, as the original does, where it carried the time of the login. Same position and size; the day's luck of the fortune house does not depend on it in our server.
- Fixed: the database backup works for a server owner who runs PostgreSQL in Docker and has no PostgreSQL tools on the PC. When `pg_dump` is not on PATH, `tposeidon backup`, the panel's backup button and the backup offered by `tposeidon start` after an update find the running container that publishes the saved database host and port (`docker ps`) and run `pg_dump --format=custom` inside it, writing the same file in the same folder. ### World and combat

- Walking, running, resting, emotes and the posture shortcuts, portals and map changes, with other players, NPCs and monsters appearing around you. The world map window.
- Combat with melee, hammers and guns, damage, monster deaths, drops and pick-ups, experience and level-ups, death and restart in town.
- No caps on the server: damage, HP, MP, EXP, TM EXP and Galder are 64-bit on the server and in the database. The client shows at most 2,147,483,647 of any value, and the server sends that maximum instead of letting the number wrap. Optional limits are in `data/server_rates.json`, where `0` means no limit.
- Player versus player in PK zones, and 1v1 duels.
- Skills: learning from cards, the skill shop, mastery and job change.

### Items and economy

- Bag, equipment, NPC shops, bank, warehouse, mail and gifts.
- Refining, compounding, reforming, melting, composing and decomposing, slot extension, recycling and coupon exchange.
- Special-use items, key boxes with their window, gift boxes and the microphone.
- Unique and absolute unique items and their duty rules.
- Player shops with search, the find-shop helper, visitor counters and stock updates for every visitor, and My Camp.
- Cash shop through a small built-in web shop (the catalogue starts empty).

### NPCs and quests

- Talking to NPCs, shops and quests: take, progress and turn in. Party quests. Monster quests with a weekly ranking.
- A large part of the original NPC functions, including warp gates, limited teleports, summons and daily checks.
- NPC scripting: write your own NPCs, quests and events in plain text files, with `tposeidon scripts check` and `tposeidon scripts reload`. See the [scripting reference](docs/scripting/README.md).

### Social

- Parties, the party recruit board and friends across game servers, including where a friend is. Guilds, instant chat rooms, whispers and notices.
- Guild games and the guild ladder.
- Couples, the wedding hall, the wedding board, marriage options and divorce.
- Angels (the newbie helper system).

- Drilling and auto drilling, surprise spots and treasure maps.

- Soul seeds, the soul system and honor titles.

### Game master tools

- GM chat commands start with `@` (`@login <password>`, `@kick`, ...), because the KR 2014 client keeps every `/` line for itself. A GM line is never shown to other players, and only the registered GM character with its account password from a permitted address can log in. The GM eagle can be switched on and off from the panel or with `tposeidon gm game-flag on|off`.
- Teleport, kick (with a reason), blocks by type and sanctions, penalties, memos and notices.
- Spawn monsters, NPCs and items, on the GM, on a map or on chosen coordinates, summon, hide and show NPCs, set the music.
- OX quizzes, EXP and ability events, guild tools and GM character registration.
- Everything is available as `tposeidon gm <command>` and in the panel's GM window.

### Known gaps

- Some systems are built but have not been played live yet. They are marked in SYSTEMS.md.
- A few original features are not built yet, among them party follow, Shadow World, the guild depot, the guild Monster Match and watching a guild game. SYSTEMS.md says which and why.
- The control panel has only been tried on Windows.
- Linux and macOS packages are built the same way but have been tested less.
